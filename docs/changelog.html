NOVA FEATURE

1. Telemetria e Alerta de Bateria do Servidor Web

service / web

Permite que qualquer desenvolvedor conectado via navegador monitore o consumo de energia do aparelho físico Android que hospeda o servidor, prevenindo desligamentos inesperados no meio do desenvolvimento de uma sprint.

Arquivos Modificados & Criados:

  • ServerBatteryProvider.kt: Registra um BroadcastReceiver para Intent.ACTION_BATTERY_CHANGED e extrai nível percentual, se está em carga e o tipo de tomada (AC, USB ou Bateria).
  • ServerApiController.kt: Expõe o endpoint JSON GET /api/v1/server/battery e /api/v1/server/telemetry.
  • jira.css: Criadas classes de estilo .server-battery-pill, .server-battery-toast com pulso luminoso animado e alerta em vermelho para carga < 20%.
  • Templates HTML (jira_board.html, jira_backlog.html, jira_projects.html, jira_reports.html): Inserido o indicador dinâmico no topo e script assíncrono com polling inteligente a cada 30 segundos.
CORREÇÃO DE SEGURANÇA

2. Resolução do Alerta "Não Seguro" em https://sprintt.local

security / assets

Os navegadores modernos (Chrome, Edge, Firefox) rejeitavam o certificado por ausência de Subject Alternative Name (SAN) cobrindo o endereço mDNS sprintt.local.

Ações Realizadas:

  • Regenerado o keystore PKCS12 (app/src/main/assets/keystore.p12) via mkcert com SANs ampliados: sprintt.local, *.sprintt.local, ticketmaster.local, localhost, 127.0.0.1 e ::1.
  • Adicionado o certificado raiz da CA em app/src/main/assets/static/rootCA.pem e docs/rootCA.pem.
  • RootWebController.kt: Criadas as rotas GET /cert/rootCA.pem e GET /rootCA.pem para permitir download do certificado em 1 clique.
  • Integrado o componente modal #sslModal com passo a passo ilustrado de instalação em todas as páginas web.
BUGFIX

3. Isolamento Estrito de Tickets na Sprint Ativa

web / kanban

Corrigido o comportamento em que tickets do Product Backlog ou de sprints futuras apareciam no quadro Kanban da Sprint Ativa quando o projeto não possuía uma sprint ativa iniciada.

Mudanças no Código:

  • JiraWebController.kt: Refatorada a função buildBoardModelAndView(). O fallback anterior repo.getIssuesByProject(activeKey) foi substituído por emptyList() caso nenhuma sprint esteja com status ACTIVE.
  • jira_board.html & jira_kanban_grid.html: Adicionada a flag condicional Mustache {{#hasActiveSprint}} ... {{/hasActiveSprint}}. Quando inativa, o quadro apresenta uma mensagem amigável com botão de ação rápida direcionando para o Backlog.
  • Modal de criação rápida no Kanban atualizado para injetar automaticamente o activeSprintId nos novos tickets.
NOVA INTERFACE

4. Aba Analítica Nativa no Aplicativo Android

ui / mobile

Inclusão de uma tela nativa de inteligência de projeto diretamente no aplicativo móvel para acompanhamento de métricas sem necessidade de abrir o navegador.

Componentes Criados:

  • fragment_analytics.xml: Layout com seletor de projetos, card de saúde da sprint (taxa de entrega percentual e burndown), barras de distribuição por status (TODO, IN PROGRESS, DONE), gráficos por tipo de tarefa (Story, Task, Bug, Epic) e carga de trabalho por membro da equipe.
  • AnalyticsFragment.kt: Fragment que consome o banco de dados Room (TicketMasterRepository) de forma reativa e atualiza os indicadores em tempo real.
  • MainActivity.kt: Adicionada a aba "Analíticos" ao TabLayout e configurada a alternância suave no FragmentManager, ocultando o FloatingActionButton quando a aba analítica estiver visível.
DOCUMENTAÇÃO

5. Suíte de Documentação e Deploy no GitHub Pages

docs / pages

Criação da pasta estática docs/ na raiz do projeto contendo toda a documentação da arquitetura do sistema, manuais de segurança e referências de API, otimizada para publicação gratuita e instantânea via GitHub Pages.

Itens Integrados:

  • docs/index.html: Portal de documentação com visão geral, arquitetura cliente-servidor, guia passo a passo para SSL, tabela de endpoints REST e instruções de ativação.
  • docs/changelog.html: Histórico detalhado de alterações (esta página).
  • docs/style.css: Folha de estilos moderna com design escuro, tipografia de alta legibilidade e responsividade total.
  • docs/rootCA.pem e docs/assets/rootCA.crt: Arquivos de certificado para download direto pelos usuários do sistema.
