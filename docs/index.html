🔋 Notificação de Bateria do Servidor Web

Como a interface web comunica a saúde energética do aparelho servidor.

O módulo ServerBatteryProvider.kt registra um BroadcastReceiver com Intent.ACTION_BATTERY_CHANGED diretamente no contexto do Android. As páginas web (Board, Backlog, Projetos e Relatórios) realizam polling periódico a cada 30 segundos no endpoint /api/v1/server/battery e exibem uma notificação toast automática:

Indicador no Cabeçalho Web:
Servidor: 85% (Carregando AC)
Endpoint JSON: GET /api/v1/server/battery

🔒 Como Eliminar o "Não Seguro" (SSL/mDNS)

Instruções passo a passo para confiar na Autoridade Certificadora Local (CA).

1

Baixar o Certificado Raiz CA

Faça o download do arquivo rootCA.pem gerado especificamente para a rede do Sprintt.

📥 Download rootCA.pem
2

Instalação no Google Chrome / Chromium / Linux

Abra chrome://settings/certificates → aba Autoridades → clique em Importar → selecione o rootCA.pem baixado → marque a caixa "Confiar neste certificado para identificar sites" → Concluir.

3

Instalação no Mozilla Firefox

Abra about:preferences#privacy → role até Certificados → Ver Certificados → aba Autoridades → Importar → selecione rootCA.pem → marque "Confiar nesta autoridade para identificar sites".

4

Instalação no Windows / macOS

Windows: Clique duas vezes no rootCA.pem (ou renomeie para .crt) → "Instalar Certificado" → Máquina Local → Selecionar "Autoridades de Certificação Raiz Confiáveis".
macOS: Dê duplo-clique no certificado para abri-lo no "Acesso às Chaves" (Keychain Access) → adicione ao chaveiro "Sistema" → selecione "Obter Informações" e marque "Confiar Sempre".

🎯 Isolamento da Sprint Ativa

Garantia de coerência ágil entre o Backlog e a Sprint em Andamento.

✓ Comportamento Corrigido

Anteriormente, projetos sem sprint ativa carregavam a totalidade dos tickets do projeto no quadro. Com a refatoração no JiraWebController.kt e no template jira_board.html:

  • Se não houver sprint ativa: o quadro renderiza um aviso elegante indicando que nenhuma sprint está em execução, com botão de atalho para planejar e iniciar uma sprint no Backlog.
  • Se houver sprint ativa: apenas tickets pertencentes a sprint.id == activeSprint.id são listados nas colunas TO DO, IN PROGRESS e DONE.

📡 Especificação da API REST

Principais endpoints disponíveis no NanoSpring Server (porta 8443 TLS).

Método Endpoint Descrição Resposta Exemplo
GET /api/v1/server/battery Retorna o estado da bateria do celular servidor {"level":85, "isCharging":true, "plugType":"AC"}
GET /api/v1/projects Lista todos os projetos cadastrados [{"id":"uuid", "name":"Sprintt", "key":"SPR"}]
GET /api/v1/sprints?projectId={id} Lista as sprints associadas a um projeto [{"id":"sprint-1", "status":"ACTIVE"}]
GET /api/v1/issues?sprintId={id} Filtra os tickets estritamente pela sprint ativa [{"id":"issue-10", "title":"Fix Bug"}]
POST /api/v1/issues Cria uma nova issue no projeto/sprint {"id":"new-uuid", "status":"TODO"}
GET /cert/rootCA.pem Download direto do certificado raiz da autoridade Arquivo binário/texto PEM

🚀 Como Fazer o Deploy no GitHub Pages

Instruções simples para publicar esta documentação com link público.

1

Enviar a pasta docs para o GitHub

Faça o commit e push das alterações para o repositório remoto:

git add docs/ git commit -m "docs: adiciona documentação do Sprintt para GitHub Pages" git push origin main
2

Ativar o GitHub Pages no Repositório

1. Acesse o seu repositório no GitHub → aba Settings.
2. No menu lateral esquerdo, clique em Pages.
3. Em Build and deployment > Source, selecione "Deploy from a branch".
4. Em Branch, selecione main e a pasta /docs.
5. Clique em Save. Em poucos minutos o site estará disponível publicamente!
